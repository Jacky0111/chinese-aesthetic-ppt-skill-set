# Ruyao Sky Blue Slide Design

## Invocation and resources

Resource paths are relative to the folder containing this `SKILL.md`. Read `assets/README.md` and `references/sources.md` first, and view at least the primary reference `assets/ruyao-blue-reference.png`. When the task involves glaze tones, crackle detail, information slides, or component translation, consult the matching examples in `assets/examples/` as needed.

These images are for extracting Ruyao sky-blue color, gloss, translucency, fine crackle, flowing glaze, and deep-blue accents. They are not fixed page templates. Do not copy a full composition, element placement, or page copy; design each slide afresh from the type, length, density, and logic of the input.

## Design rules

- **Content-driven composition:** Choose proportions, layout, focal point, and information components from the content; use a specific aspect ratio only when the user or presentation environment requires it. Do not make a quiet pale background, a centered title, or any example layout the default.
- **Color:** Build on milk white, pale Ruyao celadon, mist blue, and deep ink or cobalt blue. Blue should be visible in the main elements such as titles or labels, dividers, icons, illustrations, and accents. Use ink blue where text needs strong contrast. Avoid unrelated vivid colors; natural skin tones and a few content-related neutrals are acceptable.
- **Reference swatches:** porcelain white `#DBE0DD`, Ruyao celadon `#A4BFBB`, glaze shadow `#739392`, ink blue `#244150`, deep blue `#245071`. These are sampled references, not mandatory flat fills; keep soft tonal variation.
- **Material and texture:** Convey material through gentle glaze gradients, translucent layers, soft gloss, low-contrast fine crackle, and flowing color. Texture may extend into backgrounds, cards, charts, or dividers as the content requires; keep dense detail away from small body text. Ceramic styles express a visual feeling and do not require a ceramic object.
- **Components:** Design charts, timelines, cards, and illustrations around data and content relationships. Use deep blue as a clear but restrained accent and avoid heavy decorative borders.
- **Illustration:** Keep content illustrations clearly distinct from the celadon background. Prefer clean contemporary editorial or flat vector work with clear lines, simple geometry, and limited shading, in celadon and blue.
- **Typography:** Set body text in a black or deep ink-blue Song-style face (or one of similar character for other scripts) with a clear title and body hierarchy. Use expressive calligraphy only when the user asks for calligraphic elements; all other slide text stays legible and restrained.
- **Hierarchy:** Arrange titles, body, and key information by content density; do not force one point per slide. Keep a readable hierarchy without overflow, emptiness, or over-decoration.

## Avoid

- Watercolor or ink-wash content illustrations, unless the user asks.
- Photorealistic or painterly scenes blended into the ceramic background; keep background and content illustration visually separate.
- Decorative motifs, icons, gradients, or accent colors unrelated to the content or the celadon-blue family.
- Writing slide copy on your own. Keep the user's wording; ask first if a missing label or claim would change the meaning.
- Absolute paths on a personal computer. Reference every image relative to the skill folder, selected through the asset index.

## Multilingual output

This section takes precedence over any other statement in this skill about language, typefaces, or reading direction.

- **Instruction language is not output language:** This file is written in English; it does not set the language of the presentation.
- **Choosing the output language automatically:** Follow the user's explicit choice. Otherwise infer it from the language and intent of the current input (slide content, request wording, context). No language is fixed, and neither the repository nor the instruction language is a default. Any language and mixed-language content are in scope.
- **Preserve the user's wording:** Never translate, rewrite, convert between Simplified and Traditional Chinese, or transliterate supplied content on your own initiative, including names, quotations, code, numbers, and units. Translate only when explicitly asked. Supplied text must appear character for character, including punctuation, capitalization, numbers, and units: add no terminal punctuation and swap no marks; line breaks may move but must not add or remove characters. If the requested output language differs from the supplied text and translation was not mentioned, no fixed follow-up question is needed: decide the language of newly written text from the user's input and keep the supplied text as it is.
- **Fit layout to the text:** Adjust type hierarchy, line breaks, columns, and slide count to actual text length. Do not force content in by shrinking it past legibility or clipping it.
- **Font coverage:** Use an available font that covers the target script, with no missing or invented glyphs. Where this skill names Song-style or sans-serif character, pick a serif or sans-serif of similar character for other scripts.
- **Reading direction:** For right-to-left scripts such as Arabic and Hebrew, mirror alignment, reading order, timelines, and process flow, keeping numbers, Latin words, and punctuation correct in mixed text. Use vertical setting only when the script supports it and the content calls for it.
- **Scope:** This section governs presentation content and layout. Layout advice, including calls for short captions, does not authorize cutting or condensing the user's wording. If supplied text conflicts with checkable history or this skill's historical boundaries, point it out and change it only after the user confirms.
- **Change the language, keep the style:** Preserve this skill's color, material, texture, gloss, depth, character, and atmosphere. Chinese text in example images is sample text: do not copy it or treat it as the default language.
- **Check before delivery:** When calling image generation, quote the slide text exactly in the prompt and state that no punctuation may be added, removed, or replaced. Before delivery, compare the text actually rendered with the user's text character by character, including the end of every line; fix or disclose any difference, and report what the image really shows. Also look for missing glyphs, misspellings, broken lines, and direction errors. If image generation cannot render a script reliably, use editable text layers; if that is not possible, tell the user.
